# WorkBuddy、Claude 与其他智能体

Chrome 操作助手提供标准**本地 stdio MCP**。Chrome 扩展和本机 Go 服务可以复用；只有各智能体的连接配置入口不同。当前自动安装配置面向 Codex，WorkBuddy / Claude 提供配置和说明，尚未在这些客户端内完成实机验收。

v0.2.0 提供26个工具。截图工具会返回真实 MCP 图片内容和本地 PNG 路径，客户端需支持图像输入才能进行视觉定位；只显示文字的客户端仍可读取结构化网页，但不能把文件路径当作已经看到了图片。请使用包内最新操作技能，按“先观察、按需截图、动作后核实”的流程执行。Chrome 最低版本125。

| 客户端 | 接入方式 | 当前验证状态 |
|---|---|---|
| Codex | Codex 插件安装器 | 标准 MCP 调用与浏览器流程已验证；常用 Chrome 手动加载后在新任务验证 |
| WorkBuddy 本地客户端 | 自定义 MCP / 连接器，type=stdio | 官方文档确认支持；待客户端实机联调 |
| Claude Code | claude mcp add，本地 stdio | 官方文档确认支持；待客户端实机联调 |

## 生成当前电脑的配置

先运行安装工具并手动加载 Chrome 扩展。如果只使用 WorkBuddy 或 Claude，可以选择安装包中的“仅安装浏览器组件”工具，不必配置 Codex。

运行包中的 `导出MCP配置-Windows.cmd`，或 Mac 的 `/bin/bash ./导出MCP配置-macOS.sh`。生成 `MCP配置.json`，其中的程序路径是当前电脑的实际安装位置，不需要手工填写路径，也不包含 API Key。

等价命令是 `browser-bridge.exe mcp-config`（Mac 为 `./browser-bridge mcp-config`）。输出包含 `mcpServers.browser_bridge`、`type: stdio`、程序绝对路径和 `args: ["mcp"]`。

请将其中的本产品条目**合并**到客户端现有 MCP 配置，不覆盖其他服务配置。更新或回滚之后重新导出，以引用实际启用的版本路径。

## WorkBuddy

在本地客户端的自定义 MCP / 连接器配置处使用生成的 JSON，启动方式选择 stdio。每个连接器只配置本产品这一个 MCP 服务。默认可访问所有普通网站，不需要在扩展内逐个添加。Chrome 安装或升级时的扩展权限确认仍需完成。

如需 AI 使用说明，可加载本包 `plugin/skills/browser-bridge/SKILL.md`，或将其操作规则加入对应智能体的工作指引。工具本身也提供参数说明和错误处理信息。

依据：[WorkBuddy 官方连接器文档](https://open.workbuddy.cn/en/docs/connector)。本版未发布 WorkBuddy 连接器市场安装包，不承诺已经完成商店分发或所有 WorkBuddy 版本适配。

## Claude Code

使用生成的 JSON 中 command 对应的绝对路径，添加本地服务：

```text
claude mcp add --transport stdio --scope user browser_bridge -- "程序绝对路径" mcp
```

添加后进入 Claude Code，通过 `/mcp` 检查工具状态，再开始新任务。调用 `connection_status` 应看到已连接的 Chrome 配置文件。依据：[Claude Code 官方 MCP 文档](https://code.claude.com/docs/en/mcp)。

## Claude Desktop

在 Claude Desktop 的本地 MCP 开发者配置中，将生成 JSON 的服务条目合并到 `claude_desktop_config.json`，然后重新启动客户端。不要把配置填入只接受公开 HTTPS 地址的远程连接器入口。

参考：[Claude Desktop 本地 MCP](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop)、[本地与远程连接的区别](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)。本版不含 Claude 的 `.mcpb` 专用安装包。

## 多智能体并用时的规则

每项任务都要调用 session_start 建立自己的会话，不共享 sessionId 或 resumeToken，不交换文件授权。不同 MCP 进程具有独立身份；如果某个客户端让多个聊天共用一个长期运行的 MCP 进程，进程身份本身不能作为聊天隔离边界，还需验证客户端的任务管理。不要将“支持 MCP”当作“所有客户端的多任务行为都已验收”。

每种客户端都需实际验证：全网站访问、页面修改确认、停止、文件选择、截图显示、较大正文和客户端超时行为。批量任务在后台运行，通过状态工具查看进度；不依赖单次长时间工具调用。

浏览器通信保持本机 Native Messaging 和管道/socket，不为其他客户端另开公网或 localhost HTTP 控制入口。
